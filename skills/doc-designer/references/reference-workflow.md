# From references to an original document

Read for an open visual brief or a generic first draft. Use the user's actual genre and constraints; do not browse every platform or require an external service.

## 1. Discover by the reader's job

| Job | Free-to-view starting points | Inspect |
| --- | --- | --- |
| Learn / revise | [Typst Universe](https://typst.app/universe/), [worksheet galleries](https://www.canva.com/worksheets/templates/) | Worked examples, semantic labels, answer space, density and print size |
| Present a portfolio / showcase | [Editorial projects](https://www.behance.net/search/projects/editorial%20report), relevant public project reports | Interior evidence pages, artifact scale, captions and reflection |
| Analyze / recommend | [Quarto gallery](https://quarto.org/docs/gallery/), [public report archives](https://www.ingka.com/reports/) | Finding-to-evidence sequence, chart/table relationships, limitations |
| Resume / CV | Typst Universe's CV templates | Role/date alignment, long entries, reading order and page breaks |
| Explain a process | Public field guides, relevant document/worksheet galleries | Ordered actions, prerequisites, quick reference, exceptions |
| Formal submission | Supplied official template or issuing body's example | Required dimensions, order, exact wording and permitted styles |

Some platforms mix free and paid templates. Use them as references only unless the selected functionality and asset license permit the intended use. A free preview is not a free export or a reuse license. Prefer an account-free local route when needed.

## 2. Inspect the element, not the marketing mockup

Open an actual page at readable size. A report may need several interior page types; a short sheet may need one well-chosen example. Note the source, page/element, useful relationship, weakness, and proposed adaptation in working notes. Keep these out of the reader-facing document.

Distinguish **discovered**, **visually inspected**, and **reproduced/export-verified**. Do not promote one status into another. Stop searching once there is enough evidence to choose a direction.

Examples of critique: a notes template can have useful definition/example distinctions but waste space on an oversized introduction; a CV can align dates well while crowding its contact header; a colorful table can explain numeric patterns yet be inappropriate for ordinary opening hours. Transfer the useful choice, not the whole template.

## 3. Translate into measured composition

Start from content roles and usable page width. The following are original instructional recipes, not assets to copy or fixed themes. Dimensions are starting examples for A4 with 18 mm side margins: usable width 174 mm.

### Practical one-page guide

Put the purpose and opening/access information first. Separate the action sequence from the lookup information. An 80 mm process column, 10 mm gap and 84 mm reference column can fit a short guide. Use native columns; use a real table only for loan periods, specifications or other records. Give the value that changes a reader's action useful emphasis, then fit labels and contents around it. A 14-day value must remain legible rather than wrapping accidentally. Place the exception beside the process it qualifies.

Use this only when both columns can be read independently. Prefer a single column for strict sequence, large-print needs or parsing constraints. An original relevant illustration may establish context; omit it when it adds no useful signal.

### Worked learning sheet

Put one exact chart, problem or concept before its explanation. A 100 mm worked-example column, 10 mm gap and 64 mm practice column can distinguish demonstration from recall. Use meaningful writing space rather than compressing exercises into the remaining gaps. Keep formulas and units editable. Distinguish absolute difference from percentage change by showing the baseline, not only a different color. Put answers where the learner can check them without interrupting the exercise.

For dense revision notes, use topic groupings rather than forcing practice columns; for complex derivations, allow full-width working. Do not add a decorative cover to a short learning pack.

### Analytical brief

Lead with a supported finding and show its basis nearby. For a change between two periods, use paired values or another exact comparison and retain a small editable ledger. If total change is 80 and a category contributes 60, label 75% as its share of the increase; distinguish that from the percentage growth of the total. Separate observation, interpretation and a proposed next step. Keep the limitation next to the claim it constrains.

Avoid a prominent metric when it obscures the question, denominator or uncertainty. A quiet argument-led page may be more appropriate than a large numerical anchor.

### Portfolio and showcase

Select one meaningful artifact or linked sequence, show it at a useful scale, and pair it with its purpose, evidence and reflection. Use detail crops only with enough context to avoid misleading the reader. Use an authentic screenshot for an interface; use exact diagram source for a relationship. Do not turn every page into a dashboard or invented product window.

### Resume and formal pages

Use chronology, alignment and restrained type to establish hierarchy. Keep required headings and wording; prioritize a single-column reading order when machine parsing matters. Do not borrow colored sidebars, oversized displays or icon headers merely because they look attractive in another genre.

## 4. Match and verify the production route

Choose native text/tables for content that must stay editable; exact plotting/diagram tools for evidence; code artwork for short visual excerpts. Match type, line weight, accent and caption treatment across tools. Test the hardest element at its placed size before producing the rest.

For ray.so, start with the exact raw code and language, choose a theme compatible with the page, and control title, padding and background. Light code on a pale page is one option, not a mandatory style. Export an actual PNG/SVG and inspect it in the final document. If the download fails, record that limitation and use a disclosed local fallback if useful. Keep raw code beside artwork; do not put confidential code into a URL or external editor without authorization. Preserve editable code when copying is the reader's main task.

For DOCX plus PDF, export the final DOCX rather than independently recreating its layout. Retain chart data and diagram/code source. A rendered image can be excellent evidence while still needing editable surrounding explanation and accessible text.

## 5. Critique before extending

Render a representative page. Check whether the primary action or finding is visible, secondary material has a distinct role, table values fit, and the composition still works without color. Compare with the source and supplied constraints. Revise the largest concrete weakness once, then re-render affected pages. Continue when the result serves the brief; do not churn through cosmetic variants or assert quality from a lack of clipping.
