# Structure and visual character

Read when choosing a direction or diagnosing a generic redesign. User requirements and official templates take precedence over these starting points.

## Study a reference

Separate transferable design choices from subject matter: hierarchy, explanation beside evidence, semantic color, diagram typography, code treatment, and page density. Note what works and what impedes reading. Do not reproduce private content or another designer's assets to imitate the look.

For a redesign, compare before/after with the same content and paper size. Preserve required page counts, section order, citations, and brand. A prettier page that drops evidence is a failed redesign.

## Archetypes

| Use case | Useful decisions | Avoid |
| --- | --- | --- |
| Study sheet / Lernzettel | Concepts → worked examples → recall prompts; clear symbols and units, grayscale-safe emphasis, writing space | Miniature textbook pages, excessive highlighting, decorative covers |
| Portfolio | Project question, evidence at useful scale, captions explaining significance, reflection beside artifacts | Screenshot dumps, visuals without interpretation |
| Analysis / essay | Visible argument sequence, quiet typography, integrated quotations/citations | Decoration that fragments the argument or removes references |
| Decision brief | Finding early, exact comparison table, evidence, implications and limitations | Invented KPI tiles, giant cover, repeated summaries |
| Showcase / case study | One focal artifact per page/spread, deliberate detail crops, concise context, varied scale | Tiny full screenshots, invented UI, filler metrics |
| Resume / CV | Relevant experience first, readable chronology, aligned dates, restrained accent | Unverified achievements, skill bars, untested parsing claims |
| Manual / process guide | Steps with outcomes and checks; warnings beside actions; annotated images where needed | Numbered decoration masquerading as steps, distant warnings |
| Formal submission | Mandated template, dimensions, order, citation style; good typography within constraints | Replacing official requirements with fashion |

## Example systems, not default themes

| Direction | Possible visual language | Potential fit |
| --- | --- | --- |
| Instructional field guide | Dark forest ink, warm paper, moss accent, clear sans headings | Categorization and practical guidance |
| Analytical editorial | Near-black ink, white paper, restrained cobalt, serif body with sans headings | Arguments and research comparisons |
| Technical notebook | Charcoal ink, deep teal, pale code surface, sans plus mono | Engineering evidence and reproducible examples |

Do not force these palettes onto unrelated subjects. Monochrome, an institutional identity, or an expressive art-led approach can be better. Choose for audience, subject, language, and medium.

## Translate interface principles carefully

Borrow hierarchy, meaningful contrast, consistent tokens, specificity, structural variety, honest evidence, and inspection at the actual viewing size. Translate a web opening into an appropriate first page, components into paragraph/table/figure styles, responsive tests into paper/export tests, and motion sequencing into reading order.

Do not import nav bars, hover states, scroll animation, sales funnels, mandatory bento grids, arbitrary font bans, randomization, or fake application chrome. Illustration placeholder bars do not belong in complete reader-facing documents.

## Critique

Can the reader identify the purpose quickly? Does the opening begin useful work? Is hierarchy visible without color? Is the key figure large enough? Do repeated objects look related? Does each callout deserve attention? Does the result suit its subject rather than a tool default? Fix concrete faults instead of awarding unexplained scores.
