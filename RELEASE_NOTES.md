# Doc designer 0.1.1 — revised candidate

15 November 2026

The first maintainer trial was readable and technically valid but visually too generic. This revision changes the design instructions; it does not claim that the aesthetic problem is solved.

- Separate technical checks from composition, specificity, hierarchy, craft, and before/after improvement.
- Require a concrete visual organizing idea for open design briefs, rather than only a clean/professional label.
- Consider relevant free visual precedents and specialist tools before defaulting to office styling.
- Add examples of deliberate structure and component treatment, while respecting plain-format and official-template constraints.
- Preserve the earlier evidence and record the new diagnostic separately.

See [validation](docs/validation.md) for results and limits. Public launch remains pending visual acceptance.

# Doc designer 0.1.0 — initial candidate

15 November 2026

Initial usable version for designing and redesigning Word/DOCX documents and PDFs.

## Included

- A self-contained SKILL.md with purpose-led structure, typography, semantic color, tables, code, diagrams, and page review.
- Different starting patterns for study sheets, portfolios, analyses, reports, guides, resumes, and showcases.
- Free/local production routes with optional specialist tools and explicit editability/export tradeoffs.
- Preservation rules for redesigns, citations, revisions, comments, and source assets.
- Four optional references, UI metadata, and the MIT license.
- Research notes, validation evidence, and a fictional one-page before-and-after exercise.

## Requirements

An agent with file tools and suitable free authoring/rendering capabilities. The skill itself is instruction-only: no executable code, paid API, remote upload, or account dependency. Optional tools are not bundled.

## Validation and limits

See [the dated validation record](docs/validation.md) for exact scope, package hashes, findings, and runtime evidence. This is not a guarantee of universal document quality, host discovery, viewer fidelity, ATS parsing, or PDF conformance.

## Before public launch

Run the [tool-library exercise](examples/borrow-a-tool/exercise.md), review the DOCX/PDF and comparable before-and-after screenshots, then update the showcase and these notes. The repository's current visibility is preserved; no public GitHub release or visibility change is part of this preparation.
